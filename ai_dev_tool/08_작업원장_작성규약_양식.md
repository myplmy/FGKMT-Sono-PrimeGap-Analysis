# 작업원장 작성 규약과 양식

## 1. 목적

작업원장은 긴 작업이 대화 압축, 사용량 제한, 세션 종료 또는 오류로 중단되더라도 다음 Codex가
이미 끝난 단계를 반복하지 않고 **첫 미완료 단계부터** 이어갈 수 있게 하는 실행 중 정본이다.
핸드오프는 세션 종료 시점의 요약이고, 작업원장은 작업 중 계속 갱신하는 차이가 있다.

정본 경로:

```text
ai_dev_tool/work_ledgers/
```

파일명:

```text
YYYYMMDDHHmm_<작업명>_WORK_LEDGER.md
YYYYMMDDHHmm_<작업명>_WORK_LEDGER-done.md
```

- 접미사 없는 파일은 진행 중 또는 중단된 작업이다.
- `-done`은 요청 산출물, 검증, 결과 해석, 색인·정본 동기화와 핸드오프까지 모두 끝난 경우에만 붙인다.
- 실패·보류·사용자 결정 대기는 완료가 아니다. 원장 본문에 상태와 정확한 재개점을 남기고 접미사를 유지한다.
- 완료 원장은 사용자 승인 없이 삭제·덮어쓰기·내용 축약을 하지 않는다.

## 2. 언제 작성하는가

다음 중 하나에 해당하면 본작업 전에 새 원장을 만든다.

- 계획·구현·검증·보고처럼 세 단계 이상인 작업
- 실제 실험 또는 기존 actual artifact를 읽어 새 결과를 만드는 작업
- 여러 문서와 코드를 함께 바꾸는 작업
- 30분 이상 걸릴 가능성이 있거나 대화 압축·사용량 제한 중단 위험이 있는 작업
- 사용자가 작업원장을 명시적으로 요구한 작업

짧은 설명, 단일 파일 오탈자 교정, 읽기 전용 한두 명령은 원장을 생략할 수 있다.

## 3. 작성 원칙

1. **먼저 쓴다.** 본작업 전에 목적, 승인 경계, 단계와 첫 재개점을 기록한다.
2. **단계마다 쓴다.** 큰 단계가 끝날 때 상태, 파일, 명령, 결과와 다음 재개점을 즉시 갱신한다.
3. **증거를 쓴다.** `PASS`는 실행 명령, 종료코드, 핵심 수치 또는 artifact 경로가 있을 때만 사용한다.
4. **상태를 섞지 않는다.** `IMPLEMENTED`, `LOCALLY_VERIFIED`, `USER_RUN_FAILED`,
   `EXPERIMENT_PASS`, `SCIENTIFIC_NO_IMPROVEMENT`, `HOLD`를 구분한다.
5. **승인을 넓히지 않는다.** 사용자 승인 범위와 금지 항목을 원장 상단에 고정한다.
6. **기존 변경을 보존한다.** 시작 시 `git status --short`를 기록하고 이번 작업 소유 파일과 선행 변경을 구분한다.
7. **실패를 숨기지 않는다.** 실패 명령, 첫 오류, 부분 산출물, 수정 여부를 그대로 남긴다.
8. **결론을 소급하지 않는다.** 결과를 본 뒤 계획이나 gate를 바꾸면 새 revision과 사유를 기록한다.
9. **재개점은 한 문장으로 구체화한다.** 다음 사람이 바로 실행할 파일·명령·확인 대상을 적는다.
10. **완료 시 이름을 바꾼다.** 모든 단계와 최종 정합성 검증 후 정확한 경로를 확인하고 `-done`으로 이동한다.

## 4. 재개 절차

새 세션 또는 압축 이후에는 다음 순서를 따른다.

1. `ai_dev_tool/work_ledgers/`에서 이름순 최신 **비 `-done`** 원장을 찾는다.
2. 최신 `handoff/YYYYMMDDHHmm_HANDOFF.md`와 함께 읽는다.
3. `git status --short`와 원장에 적힌 파일 상태를 대조한다.
4. 완료 증거가 있는 단계는 반복하지 않는다.
5. 원장의 `현재 재개점`에서 시작하고, 실제 상태가 다르면 차이를 먼저 기록한다.
6. 새 사용자 지시가 기존 작업을 바꾸면 대체·추가 여부와 승인 경계 변화를 원장에 남긴다.

## 5. 최소 양식

```markdown
# <작업명> 작업원장

- 시작: YYYY-MM-DD HH:MM KST
- 현재 상태: IN_PROGRESS | WAITING_USER | BLOCKED | COMPLETE_PENDING_RENAME
- 사용자 승인: <승인된 범위>
- 금지·보류: <실행하지 않을 일>
- 선행 변경: <시작 시 git status와 이번 작업 비소유 파일>

## 목적과 완료조건

- 목적:
- 완료조건:

## 영향도·불변식

| 축 | 판정 | 통제 |
|---|---|---|
| 수학 정의 | | |
| 데이터·provenance | | |
| 통계·정밀도 | | |
| 승인 경계 | | |
| 산출물·비덮어쓰기 | | |

## 단계 현황

1. **IN_PROGRESS — <단계>**
2. **PENDING — <단계>**

## 단계별 기록

### YYYY-MM-DD HH:MM KST — <단계>

- 수행:
- 파일:
- 명령·검증:
- 결과:
- 문제·결정:
- 다음 재개점:

## 현재 재개점

<첫 미완료 단계와 정확한 파일·명령>

## 완료 전 점검

- [ ] 사용자 요청 산출물 완료
- [ ] 승인·비실행 경계 명시
- [ ] 자동 검증과 시각 QA 상태 분리
- [ ] 결과 색인·계획·METHODS/이론 정본 동기화
- [ ] 새 timestamp handoff 작성
- [ ] `git diff --check`와 참조 경로 확인
- [ ] 파일명을 `-done.md`로 변경
```

## 6. 완료 이름 변경 안전 절차

1. 원장 본문을 `COMPLETE_PENDING_RENAME`으로 갱신한다.
2. 원본과 목적지가 모두 `ai_dev_tool/work_ledgers/` 아래의 정확한 절대경로인지 확인한다.
3. 목적지 파일이 없는지 확인한다.
4. Windows에서는 같은 PowerShell 안에서 `Move-Item -LiteralPath <원본> -Destination <목적지>`를 실행한다.
5. 이름 변경 뒤 최신 handoff가 `-done` 경로를 가리키는지 확인한다.

이 이름 변경은 완료 표시일 뿐 Git commit이나 실험 성공 판정을 대신하지 않는다.
