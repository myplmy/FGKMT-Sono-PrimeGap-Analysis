# FGKMT-Sono 실험 착수 절차

## P0. 승인 전 준비

다음은 사용자 승인 전에 수행할 수 있다.

1. 작업지시서, AGENTS.md, METHODS.md, test_plan 정합화
2. source 코드와 합성 fixture 단위 테스트 작성
3. iterated log 독립 기준값과 base-k log 차이 검증
4. 제한 SQL parser, expression parser, high-watermark 재도출 테스트
5. 승인 게이트 우회 불가 테스트
6. Codex 스킬 미러와 보조 규약 검증
7. git ls-remote를 이용한 읽기 전용 현재 HEAD 관측
8. 신규 artifact의 `experiment_family`, `schema_version`, `runner_revision` 분리 여부 점검
9. 예상시간을 expected full path, possible early exit, hard wall로 분리
10. memory estimate와 observed peak 기록 방법을 분리하고 관측 불가 시 `not measured` 계약 고정

금지 사항:

- allgaps.sql 다운로드
- datas/raw 또는 datas/validated 실제 산출물 생성
- 실제 record 분석과 결과 표·그래프 생성

## P1. 도메인 정합 확인과 사용자 허가

사용자에게 다음 이해를 설명한다.

- G(x)는 end prime이 x 이하인 verified maximal-gap record로 복원한다.
- F는 반복 자연로그를 사용하고 H=G/F를 계산한다.
- record 사이 H 감소, 새 record에서의 회복, interval minimum과 running minimum을 분석한다.
- Wolf 관찰과 Sono 2e-17 scale 대비 격차를 정량화한다.
- 계산 범위의 패턴을 탐색할 뿐 무한 범위 정리를 증명·검증하지 않는다.

명시적 허가가 없으면 여기서 멈춘다.

## P2. 승인 후 source pin과 취득

1. W:\miniforge3\envs\FGKMT\python.exe를 확인한다.
2. 실행 시점의 원격 master HEAD를 다시 조회하거나 사용자가 지정한 commit을 쓴다.
3. 40자리 commit을 pin한다.
4. `scripts/runners/run_fgkmt_pipeline.ps1`의 Approved 경로로 allgaps.sql과 schema.sql을 취득한다.
5. metadata의 URL, commit, UTC, bytes, SHA-256을 확인한다.
6. 기존 commit 디렉터리가 있으면 덮어쓰지 않고 중단한다.

## P3. validation

1. schema와 허용 INSERT만 제한 파싱한다.
2. startprime 표현을 정확히 정수로 평가한다.
3. confirmed first occurrences를 선별한다.
4. exhaustive limit 안에서 end-ordered high-watermark를 독립 재도출한다.
5. ismax, gap, 순서, 선택적 consecutive-prime 검증을 통과시킨다.
6. 실패 row가 있으면 분석을 시작하지 않는다.
7. normalized CSV, validation report, hash를 불변 commit 경로에 기록한다.

## P4. 분석

1. canonical end-bounded interval을 구성한다.
2. F, H, interval minimum, running minimum을 고정밀도로 계산한다.
3. record 직전·직후 jump와 회복 배수를 계산한다.
4. Sono ratio H/(2e-17)를 계산한다.
5. Wolf 비교와 Cramér 보조 진단을 분리한다.
6. run-id 디렉터리에 표, summary, PNG·PDF를 비덮어쓰기로 생성한다.

## P5. 결과 검증과 해석

1. 입력·코드·환경 provenance를 대조한다.
2. 일부 행을 독립 재계산한다.
3. running minimum 비증가와 interval endpoint 성질을 확인한다.
4. 그래프 축, 단위, cutoff, 범례를 점검한다.
5. 결과와 한계를 test_result와 test_plan에 반영하고 `handoff/YYYYMMDDHHmm_HANDOFF.md`를 새로 만든다.
6. 패턴을 정리와 혼동하지 않고 추측·후속 임계값 연구 후보로만 구분한다.
7. terminal PASS, manifest, 필수 산출물, 재검증이 모두 확인되기 전에는 실험 PASS로 승격하지 않는다.
8. 그래프의 수치·파일 검증 뒤에는 사용자에게 시각검사를 요청한다.
9. 사용자가 실행한 BAT는 hash를 확인해 `test_done/*-done.bat`로 보존하고, 재시도는 새 활성 BAT로 분리한다.
10. 사용자 실행과 로그 감사의 상세 절차는 `ai_dev_tool/04_사용자실행_로그_완료이관_규약.md`를 따른다.
11. 실행 성공과 과학적 개선·정보량·가설 판정을 별도 필드로 기록한다.
12. actual artifact metadata가 틀렸다면 파일을 고치지 않고 정정 보고서 또는 새 revision을 만든다.
13. finite observed threshold를 theorem-level numerical threshold로 승격하지 않는다.
