# FGKMT-Sono 임시파일 격리·정리 절차

## 1. 목적과 기본 원칙

`tmp`라는 이름만 보고 삭제하지 않는다. 이 저장소의 `tmp`에는 단위시험 찌꺼기뿐 아니라
P005 actual 결과, P018 `READY`, exact primecount raw evidence, checkpoint가 함께 있을 수 있다.

실제 삭제는 사용자 명시 허가 후에만 한다. 기본 동작은 읽기 감사와 복구 가능한 격리다.

## 2. 분류

각 정확한 경로를 다음 중 하나로 분류한다.

- `RETAIN`: raw/result provenance, READY, checkpoint, downstream input, source
- `QUARANTINE_CANDIDATE`: 빈 test temp, 재생성 가능한 bytecode·render cache
- `USER_APPROVAL_REQUIRED`: 문서, handoff, worklog, 실행 여부 불명 runner, 참조 불명 파일

문서·handoff·worklog·raw dataset·actual result는 기본 `RETAIN`이다.

## 3. 감사 순서

1. 절대경로가 프로젝트 루트 안인지 확인한다.
2. file count, total bytes, last write time, 접근 오류를 기록한다.
3. `rg` 또는 `Select-String`으로 result report, handoff, plan, source, tests의 참조를 찾는다.
4. 최신 handoff와 active plan에서 downstream 의존성을 확인한다.
5. 소유·생성 원인을 모르면 이동하지 않는다.
6. 접근 권한 오류를 내용 0으로 해석하지 않는다.

## 4. 격리

`QUARANTINE_CANDIDATE`만 `tmp/cleanup_candidates/YYYYMMDD/<category>`로 이동한다.

- source·destination의 resolved absolute path를 먼저 검사한다.
- 기존 대상을 덮어쓰지 않는다.
- 삭제 대신 `Move-Item -LiteralPath` 같은 복구 가능한 이동을 사용한다.
- 이동 전후 항목 수와 가능한 경우 hash를 확인한다.
- 무엇을 왜 옮겼는지 `docs/review` 감사보고서에 기록한다.

## 5. 사용자 승인 뒤 삭제

사용자에게 정확한 quarantine 경로, 파일 수·byte, 보존 위험, 복구방법을 먼저 설명한다. 사용자가
그 경로의 삭제를 명시하면 다시 절대경로를 확인하고 해당 quarantine만 삭제한다. workspace root,
`tmp` 전체, unresolved variable, wildcard를 삭제 대상으로 쓰지 않는다.

삭제 후 날짜·사용자 승인 문구·삭제 경로·복구 불가 여부를 감사보고서와 최신 handoff에 기록한다.
