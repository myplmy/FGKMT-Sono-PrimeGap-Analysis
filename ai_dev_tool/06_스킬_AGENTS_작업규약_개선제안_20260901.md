# 2026-09-01 스킬·AGENTS·작업규약 개선 제안

## 1. 사용자 작업 성향에서 도출한 요구

대화와 실행 이력을 보면 사용자는 다음 방식을 선호한다.

1. 실제 heavy 계산은 사용자가 명시적으로 실행하고 Codex는 먼저 설계·toy·검증을 준비한다.
2. 성공/실패보다 정확한 상태 구분과 원본 로그·hash를 더 중요하게 본다.
3. 수학 경험이 없어도 수행할 수 있도록 일상어 예시와 복사 가능한 정확한 명령을 원한다.
4. 장시간 실행은 현재 화면의 진행 표시, heartbeat, CPU 활용상태가 보여야 한다.
5. 음성 결과나 실수를 숨기지 않고 다음 설계를 개선하는 근거로 쓰기를 원한다.
6. 중단돼도 worklog·handoff로 정확히 이어받을 수 있어야 한다.
7. 사용자가 figure의 실제 가독성을 확인하고 Codex는 수치·파일 자동검증을 담당한다.
8. 실행된 전용 runner는 hash 보존 archive, 공통 기능은 모듈화하기를 원한다.

이 성향은 AGENTS에 모두 길게 복제하기보다 짧은 불변식과 세부 절차·스킬로 분리하는 편이 좋다.

## 2. A — 유용한 스킬 제안

### 권장 1 — 기존 `log-to-result` 확장

현재 skill은 주로 P003형 `F/H/Sono/envelope` 결과를 상정한다. P014 certificate와 P018 blinded
information처럼 다른 실험군을 충분히 다루지 못한다.

추가할 profile:

- empirical-envelope: 기존 H/F/interval 검증
- recurrence: range·plateau·null·LOW_INFORMATION·figure QA
- finite-certificate: constraint coverage·slack·bound·serial oracle·acceleration false
- information-probe: blinded fields·dual partition·primecount evidence·gate role

모든 profile 공통으로 terminal marker, plan gate, artifact hash, source hash, runtime, partial/negative
result, result index, done-runner 이관을 검사한다.

권장도: 가장 높음. 새 skill보다 기존 skill의 범위를 구조화하는 편이 중복이 적다.

### 권장 2 — `runner-retirement`

목적:

- 사용자가 실행한 BAT/PS1/SH와 전용 helper를 식별
- 실행 시점 SHA-256과 log의 runner hash 대조
- `test_done/<name>-<runUTC>-done.ext` 비덮어쓰기 이관
- active path·static test·plan·handoff 참조 갱신
- 공통 runner/source와 downstream 입력은 보존

필요 이유: 완료 파일 이관은 매 세션 반복되고, 잘못 옮기면 다음 A 단계나 saved verifier가 깨질 수 있다.

### 권장 3 — `research-status-synthesis`

목적:

- theory index, latest handoff, result index, current plans를 읽음
- 정의/정리/finite exact/empirical/open/rejected를 표로 분리
- 서로 충돌하는 옛 “다음 우선순위”를 historical snapshot으로 표시
- 비전문 사용자용 예시와 관련 파일·section을 함께 생성

필요 이유: 실험 수가 늘어날수록 단일 결과보다 전체 연구방향을 다시 정렬하는 일이 중요해졌다.

### 선택 — `cleanup-audit`

삭제를 자동화하는 skill은 위험하다. 만들 경우 실제 삭제가 아니라 다음만 허용하는 좁은 skill이 좋다.

- file count/size/reference/age/ownership 읽기 전용 감사
- `RETAIN`, `QUARANTINE_CANDIDATE`, `USER_APPROVAL_REQUIRED` 분류
- 정확한 경로를 검증한 recoverable move만 수행
- 문서·handoff·worklog·raw/result는 기본 RETAIN

권장도: 중간. 우선 `ai_dev_tool` 절차 문서로 운용한 뒤 반복성이 확인되면 skill로 승격한다.

## 3. B — AGENTS.md 갱신 제안

AGENTS에는 다음 짧은 불변식만 추가하는 것을 권장한다.

1. **revision metadata 분리**
   - artifact에 `experiment_family`, `schema_version`, `runner_revision`을 별도 저장한다.
   - transport-only revision도 내부 label이 옛 runner 이름으로 남지 않게 한다.
2. **runtime 추정 세 구분**
   - expected full path, possible early exit, hard wall을 각각 보고한다.
3. **negative outcome 표현**
   - `EXPERIMENT_PASS`와 `SCIENTIFIC_NO_IMPROVEMENT/LOW_INFORMATION`을 동시에 허용한다.
4. **tmp lifecycle**
   - downstream READY/checkpoint/evidence는 tmp라도 입력 의존성이 끝날 때까지 RETAIN한다.
5. **actual memory 기록**
   - 가능하면 추정 memory와 관측 peak process-tree memory를 구분해 manifest에 저장한다.
6. **결과 artifact 불변**
   - metadata 오기라도 actual artifact는 소급 수정하지 않고 새 보고서 또는 revision으로 교정한다.
7. **process 상태 판정**
   - 한 번의 PID 조회나 조용한 console만으로 장기실행 종료를 단정하지 않는다.

넣지 말아야 할 내용:

- 개별 오류 E001–E014 전체
- 매 run의 상세 수치·hash
- 오래된 우선순위

이것들은 AGENTS를 비대하게 만들므로 오류 원장·결과 색인·최신 handoff에 둔다.
