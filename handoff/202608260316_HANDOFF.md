### 2.5 P007 modulus 30030 memory-safe 설계

P010 계획으로 분리했다.

- `test_plan/P010_P007_mod30030_memory-safe_separation.md`
- `source/finite_gap_separation.py`
- `source/finite_gap_separation_cli.py`
- `tests/test_finite_gap_separation.py`
- `scripts/experiments/p007/run_mod30030_separation_toy.ps1`

전체 `states x constraints` 행렬을 만들지 않고 source state를 chunk로 읽어 target 전체와
비교한다. NumPy 배열로 위반 개수·최대 위반을 계산하고 top-K 위반만 Python 객체로 만든다.
modulus 30030은 5,760 states이며 chunk 64의 보수적 workspace 추정은
35,901,440 bytes, 약 34.238 MiB다. 이는 scan working memory 추정일 뿐 LP solve 비용이 아니다.

floating 값은 위반 constraint 발견용이다. 최종 certificate 승격 시에는 선택된 가중치와
모든 constraints를 streaming exact integer arithmetic으로 다시 검증해야 한다. 실제
modulus-30030 scan과 LP solve는 resource guard로 막았고 이번 세션에서 실행하지 않았다.

### 2.6 통합이론 초안 비판적 검토

정본 보고서:

- `docs/review/17_20260826_prime-gap_통합이론_비판적_타당성검토.md`

핵심 판정:

- certificate compression은 연구 방향으로 타당하지만 아직 증명된 압축 정리나 탐색
  가속 알고리즘은 아니다.
- 같은 wheel residue state는 작은 소수의 나눗셈 모양만 반복하며, 실제 block의 prime
  endpoint 또는 합성수 witness를 자동 복제하지 않는다.
- `B=2` coverage union을 `[p+1,q-1]`로 둔 등식은 틀렸다. 실제 union은
  `[p+1,q-2]`이고 `q-1`은 별도 parity witness가 필요하다.
- `S=p-1`은 `p`를 이미 알아야 하므로 discovery compression으로는 순환논리다.
- 제한 없는 `S=2^k+2j`는 모든 짝수를 다시 열거하므로 압축이 아니다.
- 문서의 parity lower bound는 정확한 가정 아래 gap 존재 하한으로는 쓸 수 있지만,
  gap 부재 또는 maximal-gap 탐색 완료 증명은 아니다.
- `D=li-pi`에서 `Delta D`의 lower bound는 prime count의 upper bound를 준다. 빈 구간
  발견에는 도움될 수 있지만 빈 구간 부재를 증명하려면 방향이 반대인 lower bound on
  count, 즉 `Delta D` upper bound가 필요하다.
- non-strict `N <= R`에서는 `floor(R)`가 정수 상한이다. `ceil(R)-1`은 strict일 때만 맞다.
- `Q=-280.6166`, P23 survivor 319 등의 수치는 provenance가 없어 정본 채택을 보류했다.

P009 actual run이나 modulus-30030 runner는 아직 실행하지 않는다.

추가 결정이 필요하지만 급하지 않은 사항:

- 삭제 가능 검토용 문서를 영구삭제할지 archive로 옮길지
- P010 목표를 더 작은 count upper bound 연구와 실제 search acceleration 중 어느 쪽에
  더 무게 둘지
- P006 null model을 P009/P010보다 먼저 할지

## 7. 한국어 commit 메시지 제안

제목:

```text
P009 경계 증명과 P010 메모리 안전 설계를 구현하고 연구 정본을 정리
```

본문:

```text
- P006 10^9 figure 3개의 사용자 시각검사 PASS를 결과 정본에 반영
- 완료 PS1/SH를 test_done으로 이관하고 공통 로깅·runner·test를 scripts로 모듈화
- P009 half-open boundary witness 생성·검증기와 실패조건 toy tests 구현
- PARI/GP ECPP 설치 helper와 사용자 설치 절차 추가
- P007 modulus 30030용 chunked separation oracle, 자원 guard, toy tests 구현
- 통합이론 초안 4편의 비판적 검토와 ai_dev_tool 삭제 가능성 감사 작성
- 이론·가설·방법론을 docs/method/theory 주제별 정본으로 구조화
- 계획·방법론·결과 색인·AGENTS·핸드오프를 현재 승인 경계에 맞게 갱신

검증:
- FGKMT Python 전체 unittest 81개 PASS

실행하지 않음:
- P009 실제 10^20 block
- modulus 30030 scan/LP solve
- PARI/GP 설치
```

commit/push는 수행하지 않았다. 파일별 명시 staging을 사용하고 `git add .` 또는
`git add -A`는 사용하지 않는다.
