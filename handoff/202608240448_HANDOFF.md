## 3. P008 비판적 검토 결론

검토 정본은 `docs/review/16_P008_local-residue-state-certificate_타당성검토.md`, 실행 계획은 `test_plan/P008_local-residue-state-certificate.md`다.

쉬운 말로 설명하면, P007은 `[10^20,10^21)` 전체에서 큰 gap 수가 넘을 수 없는 매우 높은 “천장”을 준다. 그러나 어느 위치를 건너뛰어도 되는지는 알려 주지 않는다. P008은 범위를 작은 상자로 나눠 “이 상자 안에는 큰 gap이 0개”라고 안전하게 증명할 수 있는지 먼저 보는 실험이다.

방향은 타당하지만 다음 보정 없이는 실제 탐색을 안전하게 줄일 수 없다.

1. `[A,B)` 안 start-prime 수는 항상 `pi(B-1)-pi(A-1)`로 계산한다.
2. 정수 개수 상한은 유리수 상한의 `floor`를 사용한다.
3. block 안 마지막 소수에서 block 밖 다음 소수로 넘어가는 오른쪽 경계 gap을 모르면 `+1`이 남는다. 따라서 소수가 있는 block은 내부 상한이 0이어도 곧바로 전체를 skip할 수 없다.
4. 정수 `A mod M`, `B mod M`은 실제 첫·마지막 소수의 residue state가 아니다. endpoint prime을 모르면 안전한 worst-case potential `2t`를 쓴다.
5. `L_skip`의 단조성은 증명되지 않았으므로 binary search로 최대 skip 길이를 찾지 않는다.
6. 대표 block 네 개는 전체 `[10^20,10^21)` coverage가 아니다.
7. candidate 위치를 빠짐없이 만드는 정리, contiguous coverage ledger, survivor exact 검사, baseline보다 싼 runtime 증명이 추가로 필요하다.
8. `prime-gap`의 `m*P#/d` 작업 단위와 임의 x-block 사이의 누락 없는 mapping proof도 별도로 필요하다.

따라서 P008은 직접 가속기라기보다 “이 인증 방식이 가속기로 발전할 가능성이 있는가?”를 먼저 판정하는 phase-A 실험으로만 채택했다. 좋은 결과는 단순히 `C_local`이 작아지는 것이 아니다. 내부 상한 0, 오른쪽 crossing의 저렴한 해결, 전체 비용이 baseline보다 작음이라는 세 조건을 모두 만족해야 한다.
