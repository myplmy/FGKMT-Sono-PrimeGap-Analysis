결정적 타당성 판정:

- 초당 `10^12` integers라는 비현실적 하한도 약 1,249,213년
- 폭 1854마다 한 window, 초당 `10^9` windows라는 비현실적 하한도 약 673,793년

Ryzen 7 9700X 한 대로 full Rank 85→86 exhaustive를 완료하는 ETA는 시간/일 단위로 제시할 수 없고 “실행 불가능”이다. BAT는 이를 가장하지 않고 upstream official Method1/2 hash test와 minc 200/2000/10000 CPU calibration search만 수행한다.

BAT 자원:

- WSL2 Ubuntu 24.04
- CPU-only, GPU target 미빌드
- threads 8
- upstream `--max-mem 28` GiB
- `ulimit -v 31457280` KiB = 30 GiB
- fresh run-id output, no overwrite
- static `bash -n` PASS
- BAT no-flag rejection PASS

현재 WSL에 `git/g++/make/time`은 있지만 `sqlite3`, `libgmp-dev`, `libsqlite3-dev`, `libprimesieve-dev`가 없다. 사용자가 실행 전에 직접/승인하여 설치해야 한다.

## 8. P006 Plateau/Recurrence 검토

신규 파일:

- review: `docs/review/13_P006_plateau_recurrence_타당성검토.md`
- plan: `test_plan/P006_maximal-gap-plateau-recurrence.md`

핵심 수정:

- canonical end plateau: `[e_k,e_(k+1))`
- gap occurrence exposure: `A_k={p_n:s_k<=p_n<s_(k+1)}`
- `N_k=pi(s_(k+1))-pi(s_k)`
- `M_k=# exact G_k gaps in A_k`, 최초 포함
- `C_k=M_k-1`, 최초 이후 재출현
- multiplicity rate `Q_k=M_k/N_k`
- conditional recurrence rate `R_k=C_k/(N_k-1)`
- 검토용 문서의 `C_k/N_k`는 분자·분모 표본공간이 달라 주 지표로 사용하지 않음

현재 `allgaps.sql`은 모든 consecutive prime gaps가 아니므로 exact recurrence를 계산할 수 없다. 작은 `[2,10^8]` segmented-sieve pilot을 먼저 수행하고 `[2,10^9]`, `[2,10^10]` 확장은 실측 후 판단한다. `10^20` 재열거는 보류한다.

현재 FGKMT Conda에는 numpy/pandas/scipy/statsmodels가 있고 sympy/Python primesieve는 없다. 권장 production generator는 WSL `primesieve-bin`, independent count는 `primecount`다. 실제 pilot 전 사용자 설치 승인 필요:

```bash
sudo apt update
sudo apt install -y primesieve-bin primecount
```

선행연구는 Hardy–Littlewood, Gallagher, Goldston–Ledoan arXiv:1111.3380, Wolf arXiv:1102.0481, Kourbatov–Wolf arXiv:1901.03785, Lemke Oliver–Soundararajan DOI를 계획서에 링크했다.
