# To issues

1. 현재 계획과 코드 상태를 읽고 이미 완료된 작업을 제외한다.
2. 각 issue를 입력, 구현, 검증, 산출물이 연결된 얇은 수직 단위로 만든다.
3. 의존 관계, 완료 기준, 자동 검증, 사용자 확인을 명시한다.
4. 실제 maximal-gap 실행이 포함된 issue에는 사용자 승인 게이트를 별도로 표시한다.
5. 데이터 취득, validation, analysis, interpretation을 서로 검증 가능한 단계로 분리한다.
6. 먼저 로컬 초안을 제시하고 사용자 피드백을 반영한다.
7. GitHub 등 외부 tracker 게시는 사용자가 명시적으로 허가한 경우에만 수행한다.
