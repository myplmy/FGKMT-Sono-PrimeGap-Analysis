# P004 엄밀한 경계 보정 영향 분석

## 결론

P003의 end-prime 정수 interval 계산에는 수치 오류가 없다. 수정이 필요한 부분은 canonical 계산식이 아니라 문헌 대응의 표현과 별도의 start-bounded 민감도 분석이다. 권장안은 **Sono-compatible end-bounded 함수를 정본으로 유지하면서 FGKMT finite start-bounded 함수를 병렬 계산하는 것**이다.

## 영향 축별 판정

| 축 | 판정 | 근거와 조치 |
|---|---|---|
| 반복로그와 F(x) | 영향 없음 | 두 boundary 함수가 같은 iterated-natural-log F를 사용한다. |
| end-bounded 의미론 | 영향 있음 | Sono G_1 및 P003 정본으로 그대로 유지한다. |
| FGKMT finite 함수 | 영향 있음 | 원문은 `p_n <= X`인 start-bounded 함수이므로 별도 G_start를 추가한다. |
| 정수/실수 domain | 영향 있음 | 정수에서는 다음 jump-1의 minimum, 실수에서는 다음 jump 좌극한 infimum으로 구분한다. |
| dataset provenance | 영향 없음 | 동일한 commit-pinned maximal record CSV만 읽으며 새 데이터 취득이 없다. |
| 큰 정수·고정밀도 | 영향 있음 | 새 경계·bin도 Python int와 mpmath로 계산하고 100-dps 직접식으로 검산한다. |
| 승인 경계 | 영향 있음 | 사용자가 P004 실제 계산을 명시적으로 승인했지만 신규 exhaustive search까지 승인한 것은 아니다. |
| 통계·그래프 재현성 | 영향 있음 | shift와 window를 사전에 고정하고 run-id별 비덮어쓰기 산출물을 만든다. |
| 정리/경험 결론 구분 | 영향 있음 | start/end 차이와 local-envelope 민감도는 유한 계산이며 점근 정리 검증이 아니다. |
| 문서·테스트·handoff | 영향 있음 | METHODS, P004 계획·결과, 회귀시험과 신규 timestamp handoff를 동기화한다. |

## 세 접근 비교

| 접근 | 정확성 | 재현성 | 비용 | 위험 | 판정 |
|---|---|---|---|---|---|
| A. end-bounded만 유지하고 주석만 보강 | Sono 비교는 정확하지만 FGKMT finite 차이를 수치로 확인하지 못함 | 높음 | 낮음 | 문헌 대응이 불완전 | 보조조치로만 사용 |
| B. 정본을 start-bounded로 교체 | FGKMT finite에는 맞지만 Sono G_1 및 기존 P003와 불일치 | 기존 결과와 단절 | 중간 | 연구 목적과 산출물 의미가 바뀜 | 기각 |
| C. end 정본 유지 + start/end paired 분석 | 두 문헌 정의를 각각 정확히 보존 | 가장 높음 | 낮음 | 라벨 혼동만 관리하면 됨 | 권장 |

## 코드상 필요한 보정

1. `build_end_bounded_intervals`는 변경하지 않는다.
2. 별도 start-bounded interval builder와 paired 비교기를 추가한다.
3. start-bounded H에 계산한 `H/(2e-17)`은 Sono 직접 비교로 명명하지 않는다. Sono ratio는 end-bounded 결과에만 정본 의미를 둔다.
4. 새 record i의 start와 end 사이 `[s_i,e_i-1]`에서만 두 함수가 다름을 회귀시험으로 확인한다.
5. shifted bin의 비정수 경계는 정수 domain에 맞춰 `floor(left)+1`과 `floor(right)`로 변환한다.
6. x-width envelope는 record-count window와 혼동되지 않도록 log10 폭과 실제 정수 window 경계를 모두 저장한다.
7. 기존 P003 산출물은 불변으로 보존하고 신규 run directory에만 결과를 쓴다.

## 추가 이론 분석 필요 여부

real-X infimum은 문서상 보정이면 충분하고 P003 정수 결과를 다시 계산할 이유는 없다. 다만 논문과 수치표를 한 표에서 직접 비교할 때는 start/end paired 결과를 함께 제시하는 것이 바람직하다. 경계 이동량은 각 record gap 길이에 불과해 큰 x에서 상대적으로 매우 작지만, exact finite function과 jump 위치를 논할 때는 생략하면 안 된다.
