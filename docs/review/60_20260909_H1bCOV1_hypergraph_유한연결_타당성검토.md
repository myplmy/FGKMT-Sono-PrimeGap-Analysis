# H1b-COV1: residue covering의 유한 연결과 남은 C0

- 작성: 2026-09-09 KST.
- 주축: 같은 Sono 계수 2e-17의 X_cert proof. 다른 연구방향은 추후 별도 연구.
- 판정: **유한 입력 연결을 확보했으나 full hypergraph와 X_cert는 아직 OPEN.**
- 정본: [theory 53](../method/theory/53_Sono_FMT_H1bCOV1_full_residue_hypergraph_interface.md),
  [계약](../method/theory/data/Sono_FMT_H1bCOV1_hypergraph_interface_v1.json).

## 1. 이번 연구는 무엇을 해결하려는가

지금까지는 “후보가 몇 개 남는가”, “대부분의 후보가 비슷한 정도로 선택되는가”를
계산 가능한 오차식으로 만들었다. 다음은 **한 소수당 잔여류 하나씩 골라,
필요한 수만큼을 고르게 지울 수 있는가**이다. 이를 hypergraph covering이라 부른다.

예를 들어 각 청소 도구가 지울 수 있는 점의 묶음을 가지고 있다고 생각하자.
묶음들이 평균적으로 고르게 배치됐어도, 실제로 도구 하나당 하나씩 골랐을 때
너무 많이 겹치거나 어느 구간만 싹 지워질 수 있다. 기존 FGKMT 정리는 이 문제를
다루지만, 우리가 필요한 것은 “충분히 큰 수에서 된다”를 넘어서 오차와 시작
조건까지 숫자로 적힌 보증서다.

이것은 실제 소수를 더 멀리 생성하는 작업이나 CPU 시간을 길게 투입하는 실험이 아니다.
현재 병목은 **증명 사이의 조건과 오차를 연결하는 일**이다.

## 3. 새로 명확히 닫은 연결

### 3.1 예상한 점만 지웠다고 계산하면 안 된다

소수 5, 잔여류 2를 예로 들면 7, 17, 37은 모두 같은 잔여류에 있다.
tuple 안의 7과 17만 보고 “37은 남는다”고 세면, 실제 잔여류로 지울 때 37도
같이 지워지므로 틀린다. “적게 남는다”는 상계에는 쓸 수 있어도,
**얼마나 남는가의 하계**에는 문제가 된다.

따라서 이번에는 full residue 묶음 전체를 사용했다. 크기가 2k를 넘는 묶음은
일부만 남기는 대신 통째로 사용하지 않는다. 버린 비용은 기존 off-tuple
증명으로 상계한다. theory53 §§3·7의 핵심이다.

### 3.2 버린 후보는 마지막에 비용을 내고 복원한다

예외 q를 잠시 빼면 남은 후보 모두에 정리를 적용할 수 있다. 그러나 원래 후보로
돌아갈 때는 빠졌던 q가 남아 있을 수도 있다. 이 비용을 0으로 처리하지 않았다.
cap 이후 총 예외 수는 2X/(ab) 이하, 원래 후보 대비 비율은 8000/b² 이하로
보수적으로 상계했다. 여기서 a=ln X, b=ln ln X이다.

이 식의 8000은 관측된 소수 수가 아니라 **보증용 상수**다. 실제 b≈2000의
기존 child 조건에서 이 보수적 복원비가 최종 결과에 충분히 작다는 뜻은 아니다.
구간 크기와 허용 오차를 정하는 R08에서 추가로 판정한다.

### 3.3 정리의 여러 입력에 실제 숫자를 넣었다

Theorem3의 확률 재귀에서
\[
 r_{\rm hg}=2k,\quad A_{\rm hg}=4km+2,\quad
 D=2,\quad \kappa=(9/10)5^{-m}
\]
를 쓸 수 있음을 보였다. partition이 서로소·비어 있지 않도록 선택할 수 있는
확률 bound와, 1점 및 서로 다른 2점 moment를 모두 읽을 수 있는 size 조건도 확인했다.
이 과정에서 최종 Sono 계수나 기존 C의 정의를 바꾸지 않았다.

### 3.4 subset의 약속을 확대하지 않았다

미리 정한 구간에서 잘 맞는다는 것과, 결과를 본 뒤 가장 이상한 구간을 골라도
잘 맞는다는 것은 다르다. 예를 들어 남은 점만 골라 새 구간/집합을 만들면
당연히 “너무 많이 남는 집합”을 만들 수 있다.
이번 문서는 미리 정한 유한 family에만 실패율을 합산한다. 모든 subset에
한꺼번에 적용하거나 결과를 보고 subset을 고르는 권한을 부여하지 않는다.

## 4. 남은 한 핵심과 후속 의무

이번 인터페이스에서 미수치화된 core는 FGKMT의 C0이다. source는 어떤 충분히 큰
절대상수가 존재한다고 증명하지만 그 숫자를 적지 않는다.
theory53 (53.18)은 C0가 주어지면 검사할 조건을 **식으로만** 명확히 적은 것이다.
이를 X_cert 계산기라고 부르거나 임의의 C0=1을 넣지 않는다.

다음 단계 H1b-COV1a에서는 다음을 순서대로 한다.

1. Lemma5.1의 normalization 1·2차 moment를 상수까지 복원한다.
2. 조건부 moment에서 나누는 확률의 하한과 같은 index의 independent-copy 처리를 감사한다.
3. Taylor·union·귀납에서 하나의 C0로 모든 단계가 성립함을 보인다.

이후에도 R08의 동시에 성립하는 구간별 budget·smooth remainder,
R09 PAP, R10 two-prime UB, R11 최종 계수의 공통 budget,
R12 모든 큰 최종변수로의 전달은 남는다. R07–R12 6묶음은 난이도나 완료율의
비율이 아니다. 이번에 여러 입력을 닫았어도 전체 R07을 완료로 표시하지 않는다.

## 5. 오류·수정과 검증의 범위

- 앞 theory52 (52.17)에 마지막 항 앞 '+'가 빠진 표시 오류를 발견했다.
  계약 JSON·helper는 원래부터 세 항의 합이었다. theory53 §1.1에 정정했으며
  hash-pinned 원문을 바꾸거나 실제 결과를 소급 수정하지 않았다.
- 처음 toy 검사에서 “소수 modulus 최대 8개”용 validator를 “후보점 10개”에
  재사용하여 테스트 준비가 실패했다. 서로 다른 역할이므로 후보점은 32개 이하,
  개별 소수는 기존 작은 소수 검사로 확인하도록 분리했다. 큰 자료 허용으로
  경계를 느슨하게 바꾼 것이 아니며 모든 toy에 크기 제한이 있다.
- helper와 toy는 계산식·support·경계·실패율을 검산한다. core C0의 proof,
  무한 정리의 독립 심사 또는 실제 큰 X의 소수 실험을 대신하지 않는다.

검증 결과: 전용 32/32 PASS (0.081초), 관련 6module 99/99 PASS (0.266초),
정상 로컬 권한 전체 613/613 PASS (67.757초), py_compile 6파일 PASS.
JSON의 무관한 배열 서식을 원상 유지한 뒤 semantic equality를 확인했고,
최종 표적 107/107 PASS (0.279초)였다. 이는 실제 prime 실험이 아니다.
최종 commit과 인계는 이번 [작업원장](../../ai_dev_tool/work_ledgers/202609092250_H1BCOV1_WORK_LEDGER-done.md)과
새 timestamp handoff에 기록한다. 새 연구 figure는 만들지 않았다.
