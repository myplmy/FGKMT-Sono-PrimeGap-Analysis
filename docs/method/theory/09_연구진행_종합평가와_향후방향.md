# 연구 진행 종합평가와 향후 방향

## 1. 이 연구가 처음 물은 것

첫 목표는 검증된 maximal prime-gap record로 실제 계단함수 `G(x)`를 복원하고,

\[
H(x)=\frac{G(x)}{F(x)},\qquad
F(x)=\frac{\log x\,\log_2x\,\log_4x}{\log_3x}
\]

의 변화와 lower envelope를 보는 것이었다. 이 목표는 P003/P004에서 달성됐다.

그 뒤 연구는 두 갈래로 확장됐다.

1. 같은 maximal gap이 record plateau 안에서 얼마나 다시 나타나는가(P006)
2. Rank 85 이후 구간을 더 싸게 exhaustive하게 덮을 certificate/algorithm이 가능한가
   (P005, P007–P010)

두 번째 갈래는 아직 algorithm improvement가 아니라, 어떤 아이디어가 실제 개선 조건을
만족하지 못하는지 단계적으로 제거하는 연구다.

## 2. 실제로 확정된 것

### FGKMT/Sono empirical 분석

- 반복로그 정의 오류 가능성을 제거했고 base-log negative control을 유지한다.
- canonical `G(x)`는 end prime 기준이며 integer interval minimum은 다음 record end 직전이다.
- `10^20`까지 84 record를 검증하고 분석 가능한 64 intervals를 계산했다.
- global minimum `H≈37.8168604`, gap 540, `x=1,346,294,311,330`이다.
- 63 record jumps에서 `H`가 모두 회복했다.
- global minimum은 멈췄지만 최근 local envelope는 40대 초반으로 회복·변동했다.
- 저장 `F/H`와 envelope를 독립 100-dps 경로로 재계산했고 issue 0이다.
- OEIS 84개, Oliveira e Silva 자료 75개 중첩 record가 모두 일치했다.

이는 finite empirical fact다. `H`의 극한, Sono threshold, FGKMT/Sono 정리 자체를
검증한 것은 아니다.

### 경계 민감도와 recurrence

- start/end 경계 차이는 짧은 record-gap 내부 windows에만 생겼고 P003 핵심 minimum을
  바꾸지 않았다.
- P006 `[2,10^9]`에서 50,847,533 consecutive gaps, complete/censored plateau 29/1을
  exact 처리했다.
- complete 29개 중 11개 record에서 recurrence가 관측됐다.
- 수치·artifact·사용자 figure QA가 모두 PASS다.
- P011 stationary leave-plateau-out null에서는 primary 관측 재발 9에 기대 109.079로
  enrichment가 지지되지 않았다. 이 큰 부족은 새로운 repulsion 정리라기보다 `x`에 따른
  gap 분포 변화를 무시한 global null의 부적합을 우선 뜻한다.

### 도구와 finite certificate

- P005 `prime-gap` CPU pipeline은 Ryzen 7 9700X/WSL의 작은 bounded calibration에서
  정상 작동했다. 이는 Rank 85→86 exhaustive coverage 증명이 아니다.
- P007 modulus-2310 certificate의 `N_over1856<=439,161,464,927,854,179`은 exact
  integer verification을 통과한 유효한 전역 count upper bound다.
- modulus 30→210→2310에서 상한은 단조 감소했지만 위치 정보는 생기지 않았다.
- P008 exact prime-count와 local certificate 구현은 PASS했지만 actual four blocks에서
  certified zero는 0개였다. direct tiling은 현재 형태로 음성 판정됐다.
- P009 G1 toy boundary witness와 P010 separation-oracle toy 설계가 구현·검증됐다.
- P010A modulus-2310 replay는 exact builders 2개와 chunk oracle 모두 PASS했지만 상한은
  `439,161,464,927,854,179`로 그대로다.
- modulus 배수 exact-lift 정리를 정식화하고 memory-safe exact scanner를 구현했다.
  modulus-30030 exact lift는 상한을 유지했고, 후속 G4 cutting-plane은 exact 상한을
  `436,001,550,591,586,306`으로 약 0.7195% 낮췄다. 위치 정보는 생기지 않았다.
- P009 actual `[10^20,10^20+1000)`은 internal zero와 exact boundary witness를 결합해
  certified zero 1 block을 만들었다. 전체 acceleration은 미증명이다.

## 3. 맞았던 아이디어

| 아이디어 | 왜 맞았는가 | 현재 한계 |
|---|---|---|
| end-prime interval minimum | canonical `G_end` 정의에서 정확히 도출 | real domain은 minimum 아닌 infimum |
| local envelope를 global running minimum과 분리 | 최근 변화와 과거 최저를 구분 | window 선택 민감도 필요 |
| count certificate의 exact rational verification | floating LP 오류를 최종 증명에서 제거 | 위치를 주지 않음 |
| boundary crossing을 별도 상태로 둠 | false zero를 막음 | 각 block witness 비용 |
| coverage와 rejection을 분리 | 누락과 잘못된 제거를 각각 감사 | 작은 coverage family 미발견 |
| measure first, promote later | P008 음성결과를 안전하게 확인 | 후속 이론 필요 |
| total-cost break-even gate | bound 숫자만 작아지는 착시 방지 | baseline mapping 필요 |

## 4. 틀렸거나 현재 형태로 버려야 할 내용

### 즉시 폐기

1. 반복로그를 base 2/3/4 logarithm으로 계산하는 구현
2. end-bounded interval을 start prime에서 시작하는 규칙
3. 전역 count upper bound가 줄면 자동으로 search 위치도 줄어든다는 주장
4. internal upper bound 0만으로 right-crossing까지 zero라고 하는 규칙
5. `Q=inf(Delta li-N)` 하한을 large-gap absence filter로 쓰는 연결
6. `B=2` block union이 `[p+1,q-1]`이라는 잘못된 등식
7. unrestricted `S=2^k+2j`가 후보를 압축한다는 주장
8. 같은 wheel state가 실제 prime witness 위치까지 공유한다는 주장
9. `gap>1856`만 검사해 정확히 1856인 gap을 놓치는 threshold

### 검증 전 보류

- provenance 없는 `Q=-280.6166400756`
- provenance 없는 P23 maximum survivor 319
- provenance 없는 장기 범위 상한 수치
- modulus 30030이 실제로 더 좋은 exact certificate를 준다는 예상
- 한 block ECPP witness 시간이 전체 range에 대표적이라는 예상

“보류”는 거짓으로 증명됐다는 뜻이 아니라 현재 연구의 근거로 사용할 수 없다는 뜻이다.

## 5. 버린 아이디어를 살릴 수 있는 방향

### `li-pi`

부재증명 경로에서는 제거하되, empty interval을 인증하는 gap-discovery layer 또는
heuristic priority로 재정의할 수 있다. absence에 쓰려면 반대 방향 `Delta D` 상한이
필요하다.

### block geometry

`S=p-1`의 tautological coverage는 정리로 쓰지 않는다. 대신 실제 candidate를 더 적은
phase/representative로 덮는 mapping을 명시하고, 누락 0과 compression ratio를 함께
증명하는 문제로 바꾼다.

### wheel state

actual primality를 복사하지 않고 small-prime composite cover, survivor precomputation,
constraint generation에만 사용한다. absolute endpoint는 exact proof로 닫는다.

### count certificate

전역 `C_max` 숫자만 더 낮추는 연구에서 멈추지 말고 local zero/candidate-cover와 연결될
때만 search accelerator로 승격한다. 그렇지 않으면 독립적인 finite count theorem으로
평가한다.

## 6. 권장 연구 방향

### 우선순위 1 — P010B coverage mapping 또는 다음 modulus feasibility

P010A G4는 약 21초에 수렴해 count 상한을 약 0.7195% 낮췄다. 같은 30030 LP 반복은
중복이다. 실제 알고리즘 개선을 위해서는 P010B absolute candidate-cover mapping을 먼저
정식화하거나, 더 큰 modulus의 memory-safe feasibility를 32 GB 안에서 새로 검토해야 한다.

### 우선순위 2 — P012-A local/nonstationary null 실행·감사

P011의 global stationary null은 부적합했다. 사용자가 stratified hypergeometric 설계를
사전 승인했다. P012-A r1은 분산 0인 올바른 `z=None`을 그림이 실수로 강제해 실패했고,
통계를 바꾸지 않은 r2가 로컬검증됐다. r2 actual과 saved recomputation을 감사한 뒤 계약을
동결하고서만 `[10^9,10^10]` holdout을 연다.

### 우선순위 3 — coverage theorem을 종이에 먼저 고정

실제 `gap>=1856` start가 모두 들어가는 candidate family를 식으로 정의한다. 후보 수가
전 start enumeration보다 줄지 않으면 구현하지 않는다. 이 단계가 P005 exhaustive
mapping과 모든 새 certificate 압축 아이디어의 병목이다.

### 우선순위 4 — P009 확장 조건 연구

한 block boundary proof는 PASS했지만 internal-zero block을 넓고 싸게 공급하는 방법이
없다. 이 mapping 또는 candidate cover가 생기기 전에는 boundary witness 개수만 늘리지
않는다.

### 낮은 우선순위

- P008 block length를 더 많이 찍는 prime-count sweep
- coverage 없이 Rank 85→86 장시간 search
- provenance 없는 `Q` 수치 정밀화
- modulus만 계속 키우는 dense LP

## 7. ChatGPT에게 맡길 수 있는 일

- finite lemma의 엄밀한 증명과 counterexample 점검
- candidate coverage 정의·proof skeleton·toy exhaustive verifier
- ECPP schema/parser/hash/subject 검증과 failure tests
- P010 streaming exact verifier와 modulus-2310 replay
- recurrence null model 문헌 검토와 시뮬레이션 코드
- resource sensitivity와 break-even 계산
- 결과·로그·manifest 독립 감사

열린 수론 정리를 일정 시간 안에 반드시 발견하거나, 168시간 이상 계산을 대신 실행하거나,
32 GB/100 GB 제한을 넘는 실험을 수행하는 것은 보장할 수 없다.

## 8. 사용자와 논의할 사항

1. 본 연구의 중심을 `H(x)` empirical paper와 finite certificate algorithm research로
   분리할지, 한 프로젝트 안의 두 축으로 유지할지
2. P009 single-block feasibility가 PASS해도 전체 가속 gate가 멀다는 점을 감수하고
   진행할지
3. P010의 목표를 “더 좋은 count theorem”과 “search accelerator” 중 어디에 둘지
4. P006 후속을 exact null model과 더 큰 range 중 어느 쪽에 우선할지
5. 독립 verifier를 다른 언어 또는 proof assistant로 만드는 비용을 감수할지

권장안은 두 연구 축을 문서상 분리하되 같은 provenance·verification infrastructure를
공유하는 것이다. 그러면 P007/P008의 음성결과가 P003/P004의 완성도를 흐리지 않고,
certificate 연구도 독립적인 성공 조건을 가질 수 있다.
