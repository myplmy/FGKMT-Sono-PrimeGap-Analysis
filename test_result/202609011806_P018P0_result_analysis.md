# P018-P0 blinded prefix 정보율 calibration 결과 분석

최종 갱신: 2026-09-01 18:06 KST

## 1. 쉬운 결론

P018 exact primecount 준비와 P018-P0 실행은 모두 정상 완료됐다. P0는 “recurrence가 있나?”를
검정하는 실험이 아니라, 큰 P018-A를 실행하기 전에 한 plateau를 두 번 독립 partition으로 계산해
속도·경계·정보량 저장 방식이 맞는지 확인하는 예행연습이다.

결과는 다음과 같다.

- 계산 pipeline과 저장·재검증: PASS
- P0 wall time: 약 32분 49초
- exact gap starts: 2,232,503,547개
- forced record를 제외한 같은 gap 582의 추가 발생 수: 0개
- primary positive-variance rows: 0/1
- P0 판정: `CALIBRATION_ONLY_NO_GATE`

즉 예행연습은 성공했지만, 이 한 plateau 자체에는 recurrence를 판별할 정보가 없었다. 이는 P0의
실패도 아니고 P018-A의 사전 실패도 아니다.

## 5. 속도와 P018-A 계획값

- P0 elapsed: 1,969.422초 = 약 32분 49초
- P0 exact gap starts: 약 22.33억
- A exact gap starts: 약 345.71억
- A/P0 count ratio: 약 15.4851

P0의 실제 속도를 단순 선형으로만 환산하면 A는 약 8.47시간이다. 이는 사전 계획의 7–10시간과
일치한다. 하지만 segment 크기, prime 밀도, OS scheduling 때문에 보장시간은 아니며 A hard wall
12시간을 유지한다.

자원 상태:

- 고정 FGKMT Python 3.11.16
- 물리 4코어·논리 8프로세서 affinity `0xff`
- 8 worker, native thread ceiling 1
- Windows process-tree limit 31.5 GB 적용·자식 상속
- 결과 manifest 전 사용량 29,670 bytes, 5 GB cap보다 충분히 작음
- GPU 미사용

관측 peak RAM은 별도로 저장되지 않았다.

## 6. 판정과 다음 gate

P0는 계획서 `test_plan/P018A_prefix_information_probe.md`의 **9. 판정과 해석 제한**에 정의된
성공 조건을 충족했다. 의미는 다음 셋뿐이다.

1. 실행·경계·dual partition·저장 blinding pipeline이 정상이다.
2. P0 실제 속도가 A의 7–10시간 계획과 양립한다.
3. 동결된 endpoint와 gate를 바꾸지 않고 P018-A를 실행할 기술적 선결조건이 충족됐다.

P0가 A나 B gate를 통과했다는 뜻은 아니다. P018-A도 정보량 probe이므로 recurrence enrichment
가설을 검정하지 않는다. A PASS의 최대 의미는 `REVIEW_BALANCED_B_DESIGN`이다.

이번 실행은 figure를 만들지 않았으므로 사용자 시각 QA 대상은 없다.
