## P017 화면 무출력과 CPU 사용률 확인

combined queue의 바깥 PowerShell은 `Invoke-LoggedNativeStage`가 child stdout/stderr를 임시 파일로
redirect하고 child 종료 후 main log에 합치는 구조다. 따라서 다음 문구 뒤 main 화면이 조용한
것은 현 구현에서 정상이다.

```text
[STAGE] p017-bounded-calibration-queue
```

실제 진행은 다음 파일에서 확인됐다.

```text
test_result/run_20260829T124332Z_p017_16h_p013_parallel_calibration_queue/live_console.log
test_result/run_20260829T125523Z_p017b_p013b_parallel_midrange_calibration/progress.jsonl
```

P017-A child는 약 709.687초에 PASS했다. P017-B progress는 `event=serial_sieve_progress`,
`mode=B_MID`로 단조 증가했고 확인 시점에 마지막 소수 약 `1.95e11`, 1,900 sieve chunks,
3,696,803,721 emitted primes까지 도달했다. 정지 징후가 아니다.

CPU 차이도 설계와 일치한다.

- P017-A: 완료된 P013-A serial checkpoint/analysis를 oracle로 읽고 새 계산은 8-worker parallel만 수행
- P017-B: 새 midrange oracle이 없어 single-stream serial sweep을 먼저 수행한 뒤 8-worker parallel 수행

따라서 현재 serial phase의 낮은 CPU 사용률은 구현 오류 증거가 아니다. progress에
`serial_oracle_completed`가 기록된 뒤 parallel worker events가 시작되면 CPU 사용률이 올라가는지
최종 감사에서 확인한다.

## P014-R2 actual 승격 설계

기존 P014-R2 toy는 다음을 이미 통과했다.

- feasible/infeasible certificate의 serial exact core equality
- worker 1/2/4/8 invariance
- deterministic top-k tie reduction
- synthetic modulus 30030, 5,760 states, 35,224,647 constraints 전수검사
- 실제 worker process 8개 관측, source-row coverage 무누락
- worker native thread environment ceiling 1

actual revision에서는 기존 P014 staged analysis에 명시적 `parallel` exact backend를 연결했다.
stage-A와 final certificate scan은 8-process exact scanner를 사용하지만, 저장 결과의 full
recomputation은 원래 serial scanner를 유지한다. 따라서 계산을 샘플링하거나 정밀도를 낮추지
않고 독립 oracle도 보존한다.

새 파일:

- `test_plan/P014R2_mod510510_parallel_actual.md`
- `scripts/experiments/p014/run_p014r2_mod510510_parallel_staged_certificate.ps1`
- `run_P014R2_mod510510_parallel_staged_certificate.bat`

추가 구현:

- parent-side block progress callback
- parallel backend/worker contract와 decimal 32 GB preflight
- parallel source hash·schema revision manifest 결박
- serial saved-verification backend 강제
- 4 physical/8 logical, 8 process, worker native thread 1
- decimal 10 GB disk cap, full matrix 금지

현재 P017과 CPU 경합을 피하기 위해 modulus-510510 actual/preflight와 전체 multiprocessing regression은
실행하지 않았다. 기존 8-worker toy 증거에 더해 변경된 progress 수집 경로를 1-worker exact toy로
검증했다.

## 결론

P014-R2는 정확성 계약을 유지한 별도 actual runner로 승격했지만 현재 P017 종료 전에는 실행하지
않는다. P013 연구는 계산범위를 자동 확대하기보다 P018 gate를 먼저 동결하는 방향이 합리적이다.
P017-B의 현재 낮은 CPU 사용률은 새 serial oracle을 만드는 의도된 단계이며, 현 시점에서 구현
오류나 정지 증거는 없다.
