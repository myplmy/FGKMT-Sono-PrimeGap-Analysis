## P014-R2: .NET 없는 현재 창 실시간 로그

기존 `Invoke-LoggedNativeStage`는 .NET `Start-Process`가 stdout/stderr를 임시 파일로 redirect하고
stage 종료 뒤 출력했기 때문에 장시간 동안 같은 PowerShell 창이 조용했다. 새 권장 경로는 다음과
같다.

- `scripts/common/live_native_tee.py`
- `Invoke-LiveLoggedNativeStage`

고정 FGKMT Python이 `subprocess.Popen`으로 child를 실행하고 stdout·stderr를 두 reader thread로
동시에 drain한다. 내용은 즉시 현재 화면에 표시되고 main log에도 append·flush된다. stderr는
PowerShell 5.1의 `NativeCommandError`로 오인되지 않도록 화면에는 안전한 단일 출력 채널로
mirror하지만, log에는 stream 전환 marker가 남는다. traceback, 빈 줄과 정확한 child exit code를
보존한다.

P014-R2의 preflight, targeted tests, parallel analysis, serial saved recomputation 4개 stage를 이
방식으로 전환했다. 수학 인자, exact backend, constraint coverage와 serial oracle은 바꾸지 않았다.

검증:

## P019: serial full oracle 없는 병렬 이중검증

P017-B는 serial 약 3시간 30분 뒤 parallel 약 48분을 실행했다. 새 범위에 serial 정답표가 없을
때는 병렬 한 번을 그대로 정답으로 쓰지 않고 다음을 수행한다.

1. primary partition으로 전체 범위를 병렬 전수 계산
2. 서로소인 다른 segment 수로 같은 전체 범위를 다시 병렬 전수 계산
3. exact sufficient statistics 전체 일치
4. 각 pass의 boundary·worker·merge gate 통과
5. enumeration과 다른 exact endpoint prime-count에서 얻은 gap-start count 일치

toy `[100,200)`에서 primary 8·verifier 11 segments, worker 4, expected gap count 21로 실행했다.
두 병렬 pass와 toy serial core가 정확히 같았다. non-coprime/equal partition과 잘못된 expected count
negative control도 거부해 3/3 PASS했다. prime/gap 샘플링이나 정밀도 축소는 없다.

다만 두 pass는 같은 sieve와 accumulator kernel을 공유한다. 따라서 P019는 partition·경계·merge
교차검사이지 완전히 독립적인 수학 oracle은 아니다. source가 바뀌면 P017 serial calibration을
다시 해야 한다. P018가 HOLD이므로 future P013 actual runner는 만들지 않았다.

## P018: gate 수치 보완

초안 6개 값의 뜻과 장단점, 일반 통계 문헌과 prime-gap 문헌의 적용 한계를
`docs/method/20260830_P018_gate_options_literature_review.md`에 기록했다. 세 후보 모두 현재
P013-B를 HOLD한다. full-range 권장안은 기존 균형형이다.

```text
alpha=0.025
event probability target=0.5
positive-variance rows >= 3
LOW_INFORMATION fraction <= 0.5
effect=2x
power target=0.8
```

discrete Poisson critical-count 변화를 포함해 power target에 필요한 최소 null expectation을 새로
계산했다. 균형형은 `11.269069541418046`, critical count 19이며 P013-B expectation의 약
168.7057배다. 이는 formal hypergeometric power가 아닌 planning proxy다.
