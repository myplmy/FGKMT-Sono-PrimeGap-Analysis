8개 worker의 native thread ceiling은 1이었고, completion order와 무관한 exact integer reduction을
사용했다. source row 누락·중복 징후는 없으며 full constraint matrix는 만들지 않았다. 추정상
full matrix를 만들면 최소 약 825.65 GiB이므로 streaming 검사가 필수였다.

### 3.2 제한 최적화

첫 working set 5,000개로 solver를 한 번 실행했지만 9.326초 뒤 다음 상태로 끝났다.

```text
HiGHS model_status = Unbounded
solver_success     = false
optimizer_outcome  = SOLVER_NO_CANDIDATE
```

즉 solver가 새 certificate 후보를 만들지 못했으므로 12 iteration을 모두 쓰지 않고 기존 lifted
baseline을 best certificate로 유지했다. 제한된 5,000개 제약만으로 목적함수 방향을 충분히
가두지 못했을 가능성이 가장 크지만, 이는 후속 설계에서 seed set의 boundedness를 별도 증명·toy로
검증해야 하는 원인 가설이다. 이번 결과만으로 solver나 전체 510510 LP가 본질적으로 unbounded라고
주장하지 않는다.

## 5. 수학적 의미

이번 실험이 정확히 보여 준 것은 다음이다.

1. G4 certificate를 modulus 510510으로 exact lift해도 기존 상한이 유지된다.
2. 8,524,288,932개 constraint 전체에서 위반이 없다.
3. 더 큰 modulus 자체만으로는 상한이 자동으로 좋아지지 않는다.

일상적인 예로, 같은 안전규칙을 더 촘촘한 지도 위에서 다시 점검했더니 모든 길이 안전했지만,
새로운 지름길은 발견하지 못한 것과 같다. 안전성 확인은 성공했지만 이동시간 단축은 별도 문제다.

다음은 증명하지 않았다.

- Rank 85→86 exhaustive coverage
- large gap 위치 목록
- P010B candidate-cover compression
- direct prime search acceleration
- FGKMT/Sono 무한범위 정리

## 6. 메타데이터 주의

R3는 transport만 바꾸고 R2 과학 모듈·schema를 그대로 사용했기 때문에 저장 `summary.json`,
`manifest.json`, analysis progress의 내부 experiment 문자열에는
`P014R2_MOD510510_PARALLEL_STAGED_CERTIFICATE`가 남아 있다. run ID, runner hash, log의 바깥
experiment marker와 파일 경로는 P014-R3다.

이는 수치나 hash를 바꾸지 않는 metadata label debt이며 이번 PASS를 무효화하지 않는다. 실행 후
artifact를 소급 수정해서는 안 된다. 후속 revision을 만들 때 schema와 experiment label을 revision과
분리하거나 명시적인 `runner_revision` 필드를 추가해야 한다.

## 7. 후속 권장

1. P014-R4 actual을 곧바로 만들지 않는다.
2. 먼저 5,000-constraint seed LP가 bounded가 되도록 하는 충분조건을 정리한다.
3. G4의 tight/near-tight constraints, gauge fixing, residue-family coverage를 조합한 seed 후보를 toy
   modulus에서 검증한다.
4. `bounded seed -> candidate 생성 -> full exact separation -> strict bound improvement`가 작은
   예제에서 재현될 때만 새 actual을 설계한다.

상한 숫자만 계속 낮추는 연구와 실제 search acceleration 연구는 계속 분리한다. 관련 이론은
`docs/method/theory/11_residue_certificate_modulus_lift.md`의 **중요한 한계**, 그리고
`docs/method/theory/08_algorithm_break_even_gate.md`의 **승격 단계**를 참조한다.
