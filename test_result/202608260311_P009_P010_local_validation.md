첫 py_compile 시도는 Windows 외부 프로그램에 `source\*.py` wildcard가 펼쳐지지 않아
literal filename이 전달되어 종료 1이었다. PowerShell `Get-ChildItem`으로 명시 파일 목록을
만든 뒤 다시 실행해 PASS했다. 이는 Python source 오류가 아니다.

최종 재감사 때 기본 sandbox 안에서 전체 unittest를 다시 실행하면 Python의
`tempfile.TemporaryDirectory()`가 workspace `tmp/`와 Windows `%TEMP%` 아래에 만든
디렉터리를 외부 FGKMT Python이 읽고 쓰지 못해 18개가 `PermissionError`로 끝났다.
동일한 명령을 승인된 sandbox 외부에서 즉시 재실행했고 81개 전부 PASS했다. 따라서
최종 판정은 코드 회귀가 아니라 sandbox와 외부 Conda process의 임시경로 권한 충돌이다.
이 실패가 workspace `tmp/`에 남긴 임시 디렉터리 3개는 절대경로를 확인한 뒤 삭제했고,
연구 산출물이나 사용자 파일은 삭제하지 않았다.

WSL syntax·toy 검사에서는 Windows PATH의 오래된 `D:` 항목을 WSL 경로로 번역하지
못한다는 경고가 출력됐지만 `bash -n`과 toy script는 exit 0 PASS였다. 이번 script가
필요로 하는 project path `/mnt/z/...`는 정상 해석됐다.

## P009 exactness 확인

- toy block `[100,120)`의 last prime 113과 right prime 127 exact 재검사
- 114–119 composite factor coverage hole 0
- probable-prime method 거부
- `q-p=threshold` 거부; 반드시 `<threshold`
- internal bound가 0이 아닐 때 crossing만 닫고 전체 zero로 승격하지 않음
- JSON/CSV composite evidence 상호대조
- artifact hash·비덮어쓰기 확인

PARI ECPP method는 certificate path·SHA-256·external exact verifier callback이 없으면
거부한다. 실제 subject binding과 serialization adapter는 PARI 설치 확인 뒤 남은 G2
작업이다.

## P010 메모리·coverage 확인

- modulus 30에서 chunked top violations와 brute-force builder 일치
- scanned constraint count가 전체 exact edge count와 일치
- chunk size 1과 5에서 deterministic top-K 일치
- modulus 30030: 5,760 states
- 64-row, top-1000 chunk working estimate 약 34.238 MiB
- full constraint matrix materialization 0
- 별도 승인 없는 30030 scan은 resource guard로 거부

oracle slack은 floating discovery용이다. exact modulus-30030 certificate가 생성됐다는
뜻이 아니며 최종 승격에는 모든 transition의 streaming integer verification이 필요하다.
